# ISO/IEC 29110 QA Recommendation System (research prototype)

One-page web app for an assessor:

* **Sidebar** – the three synthetic companies (A, B, C) stored in the knowledge base.
* **Assessment** – each assessed Base Practice with its score, the rating **inferred by SWRL rules**, and the evidence.
* **QA practice recommendations** – only `recommend(assessedEntity, practice)` facts inferred by the Pellet reasoner, each with its derivation.
* **Knowledge search** – Process / Activity / Role / Work product / end state / keyword, all taken from the ontology.

Company and assessment data are maintained in Protégé (`data/mock-companies.ttl`); the UI has no data entry.
Audit, decisions and limitations: [`docs/AUDIT_REPORT.md`](docs/AUDIT_REPORT.md). CQ results: [`evaluation/results/CQ_EVALUATION.md`](evaluation/results/CQ_EVALUATION.md).

## Repository layout

| Path | Content |
|---|---|
| `ontology/ISO29110V2.ttl` | Baseline ontology (never modified by scripts) |
| `ontology/extensions/assessment-recommendation-extension.ttl` | Added properties/class + revised and new SWRL rules |
| `data/mock-companies.ttl`, `data/qa-practices.ttl` | Demo ABox (generated by `scripts/generate_demo_data.py`) |
| `reasoner/` | `SwrlReasoningRunner` (Pellet 2.3.1 + OWL API 3.4.3) and its jars |
| `scripts/build_knowledge_base.py` | merge → reason → ablation → explanations → `kb/build/dataset.trig` |
| `kb/build/dataset.trig` | **Ready-to-load dataset** (asserted + inferred + explanation graphs) |
| `backend/` | Spring Boot API; SPARQL in `src/main/resources/sparql/*.rq` |
| `frontend/` | React + MUI single page |
| `evaluation/` | 34-CQ mapping, evaluation script, results |
| `tests/` | Reasoning tests, reference API used for UI fixtures |

## Run the prototype (Windows paths as used by the researcher)

1. **Fuseki** – `cd C:\apache-jena-fuseki-6.2.0` then `.\fuseki-server.bat`.
   Create dataset `ISO29110_RecommenderSystems` (TDB2 or in-memory; do **not** enable *union default graph*).
2. **Load the knowledge base** (replaces everything, so old inferences cannot remain):
   ```
   curl -X PUT -H "Content-Type: application/trig" --data-binary @kb\build\dataset.trig http://localhost:3030/ISO29110_RecommenderSystems/data
   ```
   or Fuseki UI → *add data* → upload `kb/build/dataset.trig`.
3. **Backend** – `cd backend` then `.\mvnw.cmd spring-boot:run` (http://localhost:8080/api/companies should list 3 companies).
4. **Frontend** – `cd frontend`, `npm install`, `npm run dev`, open http://localhost:5173.

Demo: select Company A (no recommendation), B (4) and C (9); open a recommendation to see the rating rule and recommendation rule.

## Rebuild after editing the ontology or data in Protégé

Needs Java 17+ and Python 3.10+ with `pip install rdflib`.
```
python scripts/generate_demo_data.py        # only if you edit the generator instead of the .ttl
javac --release 17 -cp "reasoner/lib/*" -d reasoner/build reasoner/src/iso29110/reasoning/*.java
python scripts/build_knowledge_base.py      # add --exclude-rule PartialImprovementRecommendationRule to recommend for Not_achieved only
```
Then reload `kb/build/dataset.trig` (step 2). `kb/build/reasoning-report.json` records inputs (SHA-256), rule list and counts.

## Tests

```
python tests/test_reasoning.py              # 43 checks, real Pellet runs
python evaluation/run_cq_evaluation.py      # 34 CQs -> evaluation/results/
python tests/reference_api.py               # refresh UI fixtures from the dataset
cd frontend && npm test                     # 5 UI tests (Vitest + jsdom)
```

## API

| Method | Path | Returns |
|---|---|---|
| GET | `/api/companies` | companies with an assessment |
| GET | `/api/companies/{id}/assessment` | company, project, assessment, results, recommendations + explanations |
| GET | `/api/reasoning/status` | last reasoning run (reasoner, time, inferred count, rules) |
| GET | `/api/search/options` | values for each search parameter, read from the ontology |
| POST | `/api/search` | `{process, activity, role, workProduct, state, keyword}` (any subset) → tasks |
| GET | `/api/search/task?iri=` | inputs, outputs and related Base Practices of one task |
